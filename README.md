# FootPod — milestone 1: raw data capture

Goal: get clean raw IMU data from the pod onto your laptop, so cadence, contact time and stride length can be developed against real runs.

## 1. Flash the pod

1. Arduino IDE → Preferences → Additional Boards Manager URLs:
   `https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json`
2. Boards Manager → install **Seeed nRF52 Boards** (the non-mbed one; this sketch uses the Bluefruit BLE stack).
3. Library Manager → install **Seeed Arduino LSM6DS3**.
4. Tools → Board → **Seeed XIAO nRF52840 Sense**.
5. Open `footpod_capture/footpod_capture.ino`, set `POD_SIDE`, upload.
6. Serial Monitor (115200) should show `WHO_AM_I = 0x6A` and `samples/s: ~416`.

**Sleep:** after 5 minutes without movement (even if a page is connected) the pod blinks purple three times and powers down; tap or pick it up to wake it. It never sleeps on USB power. Type `q` in the Serial Monitor to sleep right away.

Untested on hardware — expect a compile fix or two. If the IMU fails to init, the board selection is the usual culprit.

## 2. Record

```
pip install bleak pandas numpy scipy matplotlib
python footpod_logger.py --name FootPod-L --out walk1.csv
```

Watch the live line: ~416 samples/s and 0 lost/bad packets. If you see bad packets, the MTU didn't negotiate up — tell me what OS/adapter you're on.

### Or use the phone pages

The site is at **https://warrenjb.github.io/footpod/**. Open it in Chrome on Android.

- **Home** (`index.html`) lets you pick Running, Leg lifts, or Dashboard.
- **Running** (`run.html`) connects both pods (tap Connect once per pod) and shows live cadence for each foot and combined. It has a mounting check for each pod. Recording a run saves a summary to the dashboard: time, steps, cadence, and cadence every 5 s. It also gives you one raw CSV per foot, in the laptop logger's format plus an `rx_ms` phone-clock column.
- **Leg lifts** (`legs.html`) counts lying, alternating, standing side, or hanging leg raises. Each foot's tilt is measured from where it was when you tapped Start. Lying and hanging raises count one rep for both legs; alternating and side raises count left and right separately. Thresholds can be tuned for each exercise, and "Suggest from last set" sets them from your own reps.
- **Dashboard** (`dashboard.html`) shows runs (minutes per day, cadence per run, cadence during a run) and leg lifts (reps per day by exercise, left vs right), plus recent sessions with delete.

Data goes to the `situp-counter` Supabase project, in tables `footpod_runs` and `footpod_leg_lift_sets`. It uses the same login as the sit-up counter, and each user can only read or delete their own rows. If you're offline or signed out, saves wait on the phone and upload later. Shared code lives in `pod.js` (Bluetooth), `db.js` (Supabase), and `style.css`.

## 3. Check

```
python footpod_plot.py walk1.csv
```

Prints effective sample rate, peak g / dps with clipping counts, and a median cadence estimate; shows accel magnitude, gyro, and per-stride cadence.

## Test protocol

Mount temporarily (zip ties or tape on the laces), board flat, USB-C pointing toward the toe. Note the orientation — the firmware math will assume it.

1. **Bench:** pod still on the table for 10 s (gyro ≈ 0, |accel| ≈ 1 g), then rotate by hand.
2. **Walk:** 2 min indoors. Cadence should read ~100–120 spm.
3. **Treadmill:** 2 min each at 3 known speeds, e.g. `tm_6mph.csv`. Count steps for 30 s by hand once to check cadence. Known belt speed is the ground truth for stride length later.
4. **Outdoor run:** laptop in a backpack works for now.

Check clipping counts after the treadmill runs. A few clipped accel samples at foot strike are normal; lots means we revisit the range.

## Packet format (BLE notify, 236 bytes)

| Field | Type | Notes |
|---|---|---|
| t0_us | uint32 | micros() at first sample |
| seq | uint16 | gaps = dropped packets |
| n | uint8 | samples in packet (19) |
| odr_div8 | uint8 | 52 = 416 Hz |
| samples | 19 × 6 × int16 | gx, gy, gz, ax, ay, az raw; 0.070 dps/LSB, 0.488 mg/LSB |

Service `a3c40000-5f1d-4b8e-9c3a-7d1e2f3b4c50`, characteristic `a3c40001-…`.

## Case

`case/footpod_base.stl` and `case/footpod_lid.stl` (37 × 26 × 15 mm), regenerated by `case/build_case.py`.

- Print in PETG, 0.16 mm layers, 4 walls, no supports. Base open side up (the lace tunnels bridge), lid plate down.
- Stack: battery on the floor (foam tape), JST plug pair on the battery at the closed end, XIAO on foam tape over the battery with its USB-C pushed into the wall opening.
- Lid snaps on; for runs, seal the seam with a strip of electrical tape or a thin bead of silicone.
- Lacing: point the USB-C end at your toes and thread one lace crossing through each tunnel underneath.

### Ready-to-print G-code (Zonestar Z9V5 Pro)

`case/slicing/` has G-code sliced with PrusaSlicer from `z9v5pro_petg.ini`: 0.4 mm nozzle, 1.75 mm PETG, 240/235 °C nozzle, 80 °C bed, 0.16 mm layers, 4 walls, 30% gyroid, no supports.

- `footpod_base_z9v5pro_petg.gcode`: about 37 min, 1.8 m of filament
- `footpod_lid_z9v5pro_petg.gcode`: about 14 min, 0.7 m

There is also a PLA+ set from `z9v5pro_plaplus.ini` (215/210 °C nozzle, 60 °C bed, full fan): `footpod_base_z9v5pro_plaplus.gcode` (about 35 min) and `footpod_lid_z9v5pro_plaplus.gcode` (about 12 min). PLA+ is fine for test fits; use PETG for the pod you run with, since PLA softens in a hot car.

Load the PETG in extruder 1 (the start code selects T0). The start code homes and then loads the saved bed mesh with `M420 S1`. If you don't keep a saved mesh, change that line to `G29`.

Full plates, base and lid together:

| File | Parts | PLA+ time | PETG time |
|---|---|---|---|
| `footpod_1set_z9v5pro_<material>.gcode` | 1 base + 1 lid | ~47 min | ~51 min |
| `footpod_2sets_z9v5pro_<material>.gcode` | 2 bases + 2 lids (left and right pods) | ~1 h 33 min | ~1 h 41 min |
